# Contributor workflow notes

These notes summarize a simple workflow for making changes in this fork.

## Before changing files

1. Check the upstream project's contribution guide and the issue discussion.
2. Start from the branch requested by the maintainers (`beta` for normal contributions to Latch).
3. Keep each branch focused on one change.

## Opening a pull request

1. Describe the problem and the proposed change.
2. List the files changed and any checks performed.
3. Link the related issue when one exists.
4. Wait for review and respond to requested changes before merging into the upstream project.

## Keeping this fork useful

- Sync with the upstream repository before starting a new contribution.
- Avoid committing credentials, personal data, or generated build output.
- Prefer small, clearly named commits.
